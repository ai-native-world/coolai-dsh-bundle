# DSH 底座 POC · 验收判据冻结模板（D7 逐条打勾用）

> 版本 v0.1 · 2026-08-24 · simi 起草，曹天航审
> 原则：每条判据都有机器可复跑的失败证据；全绿只证明"按这套判据没找到坏"，不宣称"好"。
> 红 = 坏；黄 = 部分通过，列缺口；绿 = 按判据通过。

## A. 插件契约（@coolai/dsh-uc-workflow 本身好不好）

| # | 判据 | 验证方式 | 失败即坏 |
|---|------|---------|---------|
| A1 | 编译期 fail-closed | 喂 8 类坏合同（缺输入字段/输出无来源/类型错误/悬空步骤/重复 ID/未消费输入/无来源输出/中文 ID 乱序），全部必须编译拒绝 | 任一被接受 |
| A2 | 无 UC 特判 | 换一个非乐饮 UC 模板（如方法论仓 calculation 样例）必须能编译运行 | 出现乐饮硬编码字段/规则 |
| A3 | 合同语义与 methodology 一致 | 同语义反例子集（选自 methodology 92 项机器测试）移植版全拒 | 与原版判定不一致 |

## B. 运行确定性（跑出来的结果好不好）

| # | 判据 | 验证方式 | 失败即坏 |
|---|------|---------|---------|
| B1 | function 步骤确定性 | 同一份询价单连续两次 Run，输出逐字节一致（成本/产能/报价单） | 任何一字节不一致 |
| B2 | model 步骤受控 | 需求解析输出必须过 output schema + post_gate；失败进失败路径 | 静默放行/输出格式漂移 |
| B3 | Run 不可变 | 改一个输入值 = 新 Run，Trace 按 Run 分离 | Trace 串写/覆盖 |

## C. 可追溯（过程好不好）

| # | 判据 | 验证方式 | 失败即坏 |
|---|------|---------|---------|
| C1 | 每步留痕 | 每一步：读了什么、算了什么、Gate 判了什么、进哪条 transition，全在 session 事件流 | 任一步无记录 |
| C2 | 可回放 | 从 Run ID 可完整回放五步链路 | 回放缺步骤 |

## D. Gate 真实拦截（立项书第 4 条）

| # | 判据 | 验证方式 | 失败即坏 |
|---|------|---------|---------|
| D1 | 10 坑破坏测试 | 埋 10 个输入坑（缺颜色/缺镀膜/缺豆种/超毛利底线/缺交期/数量非法/成本缺失/日期非法/重复编号/无来源输出），检出 ≥9 并显式列出缺失清单 | <9 |

## E. 业务口径（机器判不了，交人）

| # | 判据 | 判官 |
|---|------|------|
| E1 | 报价公式/毛利率底线/交期规则与乐饮真实口径一致 | 林文婷 |
| E2 | 可解释/可追溯/确定性 + 不确定项显式上报（李总验收线） | 张总拍板 |

## F. 量化口径（立项书第四节）

- F1 单次报价链路耗时 ≤ 5 分钟（计时）
- F2 token 成本 < ¥1/次（账单对照，deepseek-v4-flash）
- F3 缺失信息检出率 ≥ 90%（= D1）

## 结论形态

✅ 通过（A-F 全绿，进入方案 B/C 决策）
🟡 部分通过（列缺口清单）
❌ 不通过（区分：底座问题 vs 我们定义问题，分别回退）
