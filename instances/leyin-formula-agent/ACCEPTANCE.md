# 乐饮 UC-RD-001｜业务验收标准

本标准验收的不是“Agent 有没有生成一份完整 JSON”，而是乐饮配方师能不能据此直接做样、可信地判断结果，并把一个可复做的小样送给客户确认。

## 1. 谁定义“好”

三种标准不能互相冒充：

| 标准来源 | 决定什么 | 不能决定什么 |
|---|---|---|
| 客户已确认的需求或标样 | 这个产品要什么卖点、用途、风味、禁忌和价格边界 | 杯测方法是否规范 |
| 乐饮批准的研发 SOP | 用哪台设备、怎样烘焙/养豆/制作、由谁记录、怎样转下一轮 | 客户是否喜欢 |
| SCA / WCR 行业方法 | 样品准备、描述性评价、偏好评价和统一术语怎样记录才可比 | 哪个风味一定适合某个客户 |

因此，“巧克力达到 4.0 分才合格”只有在客户或配方责任人明确确认了该量表、参照物和阈值后才有效。行业标准本身不会替乐饮或客户规定这个阈值。

会议中的“约 80 分配方初稿”是对初稿可用程度的口头期待，不是一张凭空存在的 100 分制评分表，本验收不使用它做伪精确打分。

## 2. 验收结论

| 结论 | 必须具备的业务证据 |
|---|---|
| `退回补充需求` | 明确指出缺什么、为什么会改变方案、由谁补充 |
| `可以开始打样` | 需求、当前豆批、配方、用量、烘焙、评价方法和责任人均可直接执行 |
| `试验无效，需要重测` | 身份、条件、记录或评价分歧使本轮不能形成可信结论 |
| `需要调整后再试` | 实测未达目标，且下一轮只修改有证据支持的主要变量 |
| `可以送客户确认` | 所有必须条件已满足，样品可复做，乐饮配方责任人已签字 |

`可以送客户确认` 不等于客户已经确认，更不等于允许量产。

## 3. 开始打样前的 Gate

### G1｜需求能指导配方

全部满足才通过：

- 产品形态和最终用途明确；
- 客户原话与系统翻译并列保留；
- 必须满足、希望满足、禁忌三类不混用；
- 价格边界有明确口径，或明确标记为待确认且本轮不以成本作硬判定；
- 标样入口已有标样身份和分析记录；
- 每个硬条件都有来源和确认人；
- 没有用 Agent 猜测补齐客户事实。

反例：只写“浓郁、低酸、适合奶咖”，却没有具体奶咖制作方式和谁来判断，G1 不通过。

### G2｜当前豆批是真的可用

全部满足才通过：

- 每个拟用原料绑定当前批次，而不只是物料大类；
- 批次准入、库存、成本和必要理化/杯测信息有数据时点；
- 当前批次缺项被明确标出，没有用历史均值或同产区印象代填；
- 本轮全部样品聚合后的领用量不超过可用库存；
- 缺料、未准入或关键检验缺失的方案进入寻源/补检，不进入小样任务。

### G3｜候选是有业务意义的选择

全部满足才通过：

- 每个候选对应明确意图，例如稳妥复用、强化目标风味、降低供应风险；
- 方案数量由需求决定，不强行凑 A/B/C；
- 两个候选至少在原料组合、关键比例、烘焙方向、成本/供应策略中的一个主要决策变量上有解释得通的差异；
- 每个候选写出预计表现、依据、不确定性和可推翻它的观察结果；
- 历史成功与历史失败都被检查；
- 预测没有被写成已经杯测过的事实。

### G4｜配方与小样任务可以不追问地执行

全部满足才通过：

- 显示比例恰好合计 100%；等分不能写成三个 33.33%；
- 各原料领用量按显示比例计算，合计等于每个样品的计划批量；
- 每个样品有唯一盲码、方案版本、物料批次、设备和烘焙方向；
- 每个样品只承担一个清晰的主要比较问题；
- 小样数按独立“配方版本 × 烘焙方向”计数；黑咖和奶咖是同一样品的两种评价，不重复算样；
- 对照样如果本轮重新制作，也计入本轮物理样数量；
- 烘焙曲线/设备记录、养豆条件、杯测日期和原始记录位置均已指定；
- 加权生豆成本被明确标为原料成本，不冒充完整成本或报价。

G1–G4 全部通过，结论才可以是 `可以开始打样`。

## 4. 试验结果的可信 Gate

### G5｜样品与记录对得上

- 回填的盲码、方案版本、批次、设备、烘焙和制作条件与任务单一致；
- 任何偏离都被记录，并判断是否仍可比较；
- 没有把不同批次、不同设备或不同制作条件的结果直接混在一起；
- 每位评价人的原始记录仍在，汇总不能覆盖原始值。

身份对不上或条件不可比时，不得评价配方好坏，只能 `试验无效，需要重测`。

### G6｜“杯中有什么”和“客户是否适合”分开

标准化黑咖评价：

- 按乐饮批准的 SOP；若采用 SCA 方法，应按 SCA-102 的样品准备与品尝机制执行；
- 使用统一术语记录香气、风味、质地和余韵，术语可依 SCA/WCR 词汇校准；
- 记录缺陷或异味，不用喜欢/不喜欢替代描述。

客户实际饮用场景评价：

- 严格按需求单约定的粉量、液量、奶/水和温度等条件制作；
- 逐条回答客户卖点、必须条件和禁忌是否满足；
- 喜欢程度或市场适配单独记录，不与描述性强度混为一项。

本 UC 采用乐饮现场讨论的“多名有辨识能力人员”要求：至少 3 名符合乐饮内部资格要求的评价人独立记录后再讨论。该人数是本 UC 的运营规则，不冒充 SCA 的普适人数标准。

### G7｜分歧不能被平均掉

出现以下任一情况，不得用平均分宣布通过：

- 任一评价人识别到客户明确禁止的缺陷或异味；
- 评价人对某项必须条件出现“达到/未达到”的分裂；
- 样品顺序、制作条件或评价环境可能造成系统偏差；
- 评价人没有使用已校准的同一术语或参照。

处理方式必须是复核原始记录、确认是否重测，并保留分歧原因。

## 5. 可以送客户确认的 Gate

### G8｜业务目标逐条通过

一个样品只有同时满足以下条件，才可建议送样：

- 所有 `必须满足` 条件逐条有本轮实测证据；
- 客户实际饮用场景达到已确认的目标表述或标样对比要求；
- 所有客户禁忌均未触发；
- 原料身份、100% 阿拉比卡等卖点和外在信息可追溯；
- 已确认的成本边界没有超出；未确认成本不能被假装通过；
- 配方师能够按任务记录复做同一样品；
- 乐饮配方责任人已签字。

`希望满足` 可以用于排序，但不能在硬条件失败时把样品“加权拉回及格”。

### G9｜结论能直接驱动下一步

每个候选必须且只能有一个动作：送客户确认、调整后再试、寻源/补检、停止、重测。任何“建议继续关注”“整体较好”“后续优化”而没有负责人、具体动作和返回步骤的结论都不通过。

需要再试时，复盘至少写清：

- 哪个预期与实测不一致；
- 下一轮修改哪个主要变量；
- 其他变量怎样保持不变；
- 预计改善什么；
- 什么结果会证明这次调整无效。

## 6. 配方师现场验收清单

### 6.1 打样前，配方师只回答四个问题

1. 我是否看得懂客户到底要什么、不要什么？
2. 我是否能直接按任务单领料和烘样，不必再问 Agent？
3. 这些候选是否真的回答了不同的业务选择，而不是凑数量？
4. 做完这一轮后，我是否一定能淘汰、保留或修改某个方案？

任一答案为“否”，不能开始打样。

### 6.2 打样后，配方师只回答五个问题

1. 样品身份和测试条件是否可信？
2. 黑咖描述与客户使用场景结果是否分别记录？
3. 哪些客户硬条件通过，哪些没有？
4. 我能否复做被选中的样品？
5. 下一步是谁、做什么、何时完成？

任一答案无法用原始记录回答，不能建议送客户。

## 7. 可量化但不伪造的运营指标

这些指标用于真实运行一段时间后的改进，不用于给单次 Demo 包装成绩：

| 指标 | 口径 |
|---|---|
| 需求一次承接完整率 | 无需退回补充即可进入配方设计的需求数 / 总需求数 |
| 可直接打样率 | 配方师无需追问即可执行的首轮任务数 / 首轮任务总数 |
| 首轮送样率 | 首轮即满足内部送样 Gate 的 Case 数 / 完成首轮有效试验的 Case 数 |
| 平均有效试验轮次 | 从需求确认到内部可送样所经历的有效试验轮次；无效重测单列 |
| 预测命中率 | 事前预测的属性/风险被同条件实测支持的项数 / 有明确预测的项数 |
| 复做成功率 | 按同一记录复做后仍满足内部送样 Gate 的样品数 / 复做样品数 |
| 历史复用有效率 | 被引用历史经验在本轮得到支持的条数 / 被引用条数 |
| 客户一次确认率 | 客户首次收到样品即确认的 Case 数 / 客户实际收到样品的 Case 数 |

会议提到“可能节省一天”只能作为待验证假设。先记录乐饮现状基线，再比较上线后的中位周期；不得先设一个五分钟目标后宣称成功。

## 8. 对抗性反例

以下输出即使排版漂亮也必须判失败：

- 客户只说“浓郁”，Agent 自己发明六个 0–5 目标区间；
- 用去年的同产区豆杯测值冒充当前批次；
- 三个候选只是 1% 比例挪动，没有不同的决策问题；
- 方案写了比例，却没有当前批次和实际领用量；
- 先生成“杯测已通过”，再等待人补记录；
- 把黑咖描述性强度和奶咖喜好合成一个综合分；
- 有人报出焦味，却被平均分掩盖；
- 小样机参数直接宣布可用于大机；
- 原料成本合规就宣称报价合规；
- 配方师未签字就写“客户可直接下单”。

## 9. 行业依据及其边界

- [SCA Coffee Value Assessment](https://sca.coffee/value-assessment/) 将物理、描述性、偏好/情感和外在信息分开，明确反对用单一分数替代完整判断。
- [SCA Coffee Standards](https://sca.coffee/research/coffee-standards/) 列出 SCA-102 样品准备与品尝机制、SCA-103 描述性评价、SCA-104 偏好/情感评价和 SCA-105 外在信息评价。
- [WCR Sensory Lexicon](https://worldcoffeeresearch.org/resources/sensory-lexicon) 提供 110 个风味、香气和质地属性及强度参照，用于统一描述语言。

奶咖、咖啡液或冻干成品的“适不适合客户”必须使用客户确认的实际用途协议；不能把标准化咖啡杯测的结论直接当成终端产品验收。
